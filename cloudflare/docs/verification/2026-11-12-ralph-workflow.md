# 공통 계약 기반 원격 랄프 루프 검증

2026-11-12 KST. 최종 배포 Worker는 `212ae657-e19f-4fa6-8f16-679acd7af99f`다. [실행 증거](2026-11-12-ralph-workflow.json)에 작업 ID, 런타임 지문, snapshot 해시, 라운드별 시작·종료 시각과 통합 로그를 기록했다.

## 검증 흐름

1. 합·곱의 함수 시그니처와 동작을 명시한 `CONTRACT.md`, 구현 파일 두 개와 고정 테스트를 하나의 불변 snapshot으로 업로드했다. 계약 파일의 해시와 각 워커의 쓰기 경로를 지정했다.
2. 초안에 워커가 없음을 확인했다. 별도 로컬 CLI 프로세스에서 승인 요청을 보냈다. 승인 응답에 Codex·Claude 작업 ID가 포함됐고, CLI가 종료 코드 0으로 종료됐다. PID가 사라진 것을 확인했다.
3. **159.202초 동안 상태 조회를 보내지 않았다.** 이후 새 조회 프로세스에서 이미 성공한 워크플로를 읽었다. 원격에서 승인부터 종료까지 93.836초였다.
4. 첫 라운드는 의도적으로 잘못된 구현을 제출하도록 지정했다. 각 워커는 인증 없는 독립 검사에 실패한 뒤 **같은 세션 ID**에서 수리했다. 두 번째 검사에서 각 테스트 2개가 통과했다.
5. 원격 스케줄러가 두 결과를 통합했다. 실제로 바뀐 파일은 `add.mjs`와 `multiply.mjs`뿐이다. 고정 계약과 테스트 파일은 보존됐다. 통합 컨테이너에서 테스트 **5개 통과, 실패 0개, 종료 코드 0**을 확인했다.
6. 완료 후 같은 계획을 다시 승인 요청했을 때 상태와 작업 ID가 같았다. 새 실행을 만들지 않았다.

두 모델의 첫 CLI 실행 구간은 **7,400ms** 겹쳤다. 두 워커의 인증 저장과 컨테이너 종료, 통합 컨테이너의 인증 부재·소스 불변·종료를 확인했다.

## 회귀와 적용 범위

중앙 `npm run check` 148개와 백엔드 `npm test` 147개가 통과했다. 타입 검사와 런타임 지문 검사도 통과했다. 백엔드 검사에는 쓰기 범위 충돌 거부, 저장 상태 복원 후 단일 통합, 체크포인트 응답 인증, 실패 후 같은 세션 재개, 재개 응답 유실 시 세션 식별자 및 인증 반환 보존이 포함된다.
