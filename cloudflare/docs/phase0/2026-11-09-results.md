# 0단계 검증 결과 — 2026-11-09

이 문서는 AWS 우선 계획 시점의 이력이다. 이후 사용자가 Cloudflare 우선, AWS 후속으로 순서를 변경했다. 최신 상태는 2026-11-09-cloudflare-results.md를 참조한다. 당시 실제 클라우드 실행은 수행하지 않았다.

로컬 sandbox 실패는 해당 Docker 설정의 관측이다. Fargate에서도 반드시 같은 결과라는 의미는 아니며 Fargate 통과로 바꿔 기록할 수도 없다. sandbox를 끄거나 privileged 권한을 추가하지 않았다.

MCP 시험 도구를 추가한 뒤 검증한 이미지 태그는 `hivemind-phase0:20261109`, Docker inspect ID는 `sha256:6551c00c5aa322e0e15e7d9cbf3b51f921de6279aac09ad28bf4b3f9d3716676`다. 앞선 CLI 기동만 포함한 이미지 ID는 `sha256:a2c29201ffe5a2dae9dc40e3f8549ea5d55ef5fdf5de84761ad5e75240acfc89`였다. 아키텍처는 amd64, 기본 사용자는 node다. 이미지는 로컬에만 생성했으며 레지스트리에 게시하지 않았다.

MCP SDK 1.32.2와 Zod 4.6.7을 잠금파일에 고정했다. 로컬 테스트와 이미지의 실제 설치가 완료됐다. MCP 서버의 직접 호출은 공식 CLI가 모델 실행 중 도구를 호출한 증거가 아니며 `mcp-fargate`는 여전히 NOT_RUN이다.

## 발견·수정한 문제

1. 첫 이미지에서 npm 설치 스크립트를 생략해 Claude native binary가 설치되지 않았다. 고정 버전 공식 패키지의 설치 스크립트를 허용해 다시 빌드했고 같은 제한 조건에서 CLI 기동을 재검증했다.
2. 사전 검사에서 Node.js의 v 접두사를 파싱하지 못하는 문제를 테스트로 재현하고 수정했다. 지원 버전 범위도 확인한다.
3. STS 응답 검증에서 임의 문자열 ARN을 허용하는 문제를 테스트로 재현했다. 계정 형식과 ARN의 계정 일치를 검사하도록 수정했다.

## 다음 작업

1. 사용자가 지정한 프로파일·리전의 유효한 AWS 로그인과 시험 예산을 확인한다. 기존 프로파일을 임의로 선택하지 않는다.
2. 해당 계정의 quota·네트워크·역할 권한을 읽기 전용으로 확인한 뒤 최소 시험 리소스를 구체화한다.
3. 원격 전용 구독 인증을 공식 로그인 흐름으로 안전하게 등록한다. 기존 로컬 세션을 자동으로 복제하지 않는다.
4. Fargate에서 non-root CLI·sandbox·자격증명 경계·MCP·서브에이전트를 검증한다. 실패 시 설계 변경을 기록하고 재시험한다.
5. 모든 필수 증거를 확보한 뒤 0단계 통과 여부를 결정한다. 아직 1단계 제품 구현을 시작하지 않는다.

지속 목표는 MVP 전체 완료다. 이 결과는 0단계 완료 보고가 아니며 1~9단계 구현이나 실제 AWS 수용 시험을 대체하지 않는다.

## 당시 재개 조건 — 현재는 해소됨

동일한 AWS 대상 미지정 조건이 최초 목표 실행과 두 차례 후속 실행에서 유지됐다. 마지막 사전 검사도 profile·region이 null이고 aws-identity가 BLOCKED임을 확인했다. 로컬 준비 범위는 끝났으며 실환경 gate를 우회해 후속 제품 구현을 시작하지 않는다. 요청한 프로파일·리전·시험 비용 상한이 제공되면 해당 대상의 인증 상태 확인부터 재개한다. 이후 원격 전용 구독 인증 등록과 실제 Fargate 시험을 진행해야 한다.

사용자 지정 후 roboco/ap-northeast-2의 STS 인증을 확인했다. AWS 대상 미지정은 더 이상 차단 조건이 아니다. AWS 실환경 구현은 Cloudflare MVP 수용 시험 이후로 이동했다.
