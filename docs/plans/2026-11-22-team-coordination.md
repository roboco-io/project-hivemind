## 범위

기존 Cloudflare 2-worker workflow에 선택적으로 typed coordination ledger와 팀 safety circuit breaker를 연결한다. 기본 flag TEAM_COORDINATION_ENABLED=false(미설정 포함). 기존 독립 검사·credential 직렬화·provider CLI 정책은 유지한다. 임의 SQL·중앙 DB 파일·모델 지정 identity를 허용하지 않는다. 모델이 판정한 완료는 submitted이고, trusted gateway가 기존 scheduler의 독립 검사 결과를 읽은 경우만 verified다.

실제 CLI에 coordination MCP 도구를 자동 노출하거나 추가 모델을 생성하지 않는다. HTTP worker protocol과 private capability 발급 port를 구현하고 모의 harness로 검증한다. production CLI bootstrap의 capability 전달/팀 도구 연결, LLM classifier, offline 자동 분석, 실제2/4/8 성능 실측은 후속이다. 이번 범위가 실제1000agent 지원/성능 입증이라고 표시하지 않는다.

### 固定 인터페이스 보정

TeamState는 workflow별 단일 team record다(전역team map 아님). TeamSpec에 endsAt:number를 필수로 둔다. Member는 선택 jobId/attempt binding을 갖고 trusted observe가 실제 scheduler job을 최초 결속한다. public worker actor는 이 binding과 일치해야 한다. verifier는 integration job 생성 후 결속한다. verified fact는 evidenceRef+snapshotId+checksPassed:true+containerStopped:true(+agent는authSynced:true)가 필요하다. stopped fact가 없는데 다른 attempt로 결속을 바꾸지 않는다.

TeamRepository.mutate callback은 동기 callback `(engine:TeamEngine)=>T`만 허용한다. Promise/thenable callback은 거부하고 network를 transaction 안에서 하지 않는다. repository method 자체는 Promise로 저장 commit을 기다린다. Cloudflare는 후보scheduler/engine를 만들고 저장 완료 뒤 publish한다. TeamStore Node DB path는trustedcontroller만 열며 worker HTTP와 분리한다.

HTTP 고정 routes: GET base(summary), /tasks,/events,/notes; operator POST /block,/review; worker POST /tasks,/claim,/heartbeat,/submit,/notes. lease response는 인증된 worker-private 응답이고 publicoperator조회에는 token/generation 비밀을 넣지 않는다. Worker capability issuer는 publicHTTP로 노출하지 않는다. TeamService.read/ tasks/events/notes/block/review/workerOperation 메서드명은T2가 조기에정해전달한다. 서버header에서 actor를 얻고 bodyidentity허용안함.

Ruling: 인증된 worker harness도 자기 팀의 safe summary/tasks/events/notes를 GET으로 읽어야 공유 원장이 성립한다. 운영자 GET은 유지하고, shared GET은 정확한 current capability+core actor guard를 거친다. block/review는 계속 운영자 전용이다. 공개 응답은 role과 관계없이 private lease/cap/key를 제외한다. 모델 CLI 도구를 자동 노출하는 범위는 여전히 후속이다.
