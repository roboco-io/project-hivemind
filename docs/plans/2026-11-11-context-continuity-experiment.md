# 컨텍스트 연속성과 작업 분할 비교 실험

## 목적

같은 모델과 구현 과제에서 작업 단위와 세션 분할이 비용, 검토 가능한 결과까지의 시간, 성공률에 미치는 영향을 비교한다. 기본 가설은 공유 컨텍스트가 큰 작업에서 한 세션을 유지하면 반복 입력과 인수인계가 줄어든다는 것이다. 독립 작업은 병렬 실행으로 시간을 줄일 수 있다. 두 효과의 크기는 실측한다.

[ROBOCO 선행 실험](https://roboco.io/posts/vibe-coding-token-experiments/)은 단일 세션과 계획 후 분할 방식의 차이를 보고했다. 여기서는 같은 변경 목록을 사용하고 작업 묶음을 중간 조건으로 둔다.

## 비교 조건

| 조건 | 세션과 배치 | 작업 공간과 결과 |
|---|---|---|
| A. 단일 세션 | 전체 변경 목록을 한 번에 전달한다. 구현·수정·검증을 한 세션에서 이어 간다 | 같은 시작 커밋의 작업 공간 하나에서 최종 diff를 만든다 |
| B. 작업 묶음 | 공유 파일·명세를 기준으로 변경 목록을 사전에 두 묶음으로 고정한다. 묶음당 한 세션으로 순차 실행한다 | 첫 결과를 적용한 작업 공간에서 둘째 세션을 시작한다. 인수인계에 걸린 시간과 사용량도 집계한다 |
| C. 독립 세션 분할 | 변경 항목마다 새 세션을 시작한다. 서로 독립인 항목을 최대 2개씩 병렬 실행한다 | 같은 시작 커밋의 개별 작업 공간에서 시작한다. 미리 정한 순서대로 한 작업 공간에 통합한다 |

첫 과제로 같은 저장소에서 독립적으로 적용 가능한 변경 4개를 고른다. 4개를 공유 컨텍스트에 따라 두 묶음으로 분류한다. 다음 과제는 공통 파일과 명세의 비중이 다른 변경 집합으로 같은 설계를 반복한다. 세 조건에 같은 목표, 변경 목록, 완료 조건을 준다. C의 병렬성이 비용 차이와 섞이는 경우 C를 동시 실행 1개로 재실행해 비교한다. A–C의 주 비교는 전체 실행 방식의 차이로 해석한다.

## 실행 절차

1. 시작 전에 저장소·커밋 SHA, 변경 4개, 묶음, 병합 순서, 필수 테스트와 검토 기준을 기록한다. 실행별 작업 공간을 초기화한다.
2. 첫 비교는 한 제공자·모델 버전으로 고정한다. 인증 범위, CLI 버전, 이미지, 도구·권한, 추론 설정, 공통 지침, 총 시간 제한과 통합 수정 한도를 맞춘다. Cloudflare는 같은 credentialId의 agent 실행을 직렬화한다. 같은 모델로 병렬 실행 가능한 환경인지 사전에 확인한다. 병렬 실행을 지원하지 않으면 전체 블록에서 C를 직렬 분할로 고정하고 병렬 시간 효과는 후속 실험으로 둔다. 인증 범위가 다른 실행은 별도로 보고한다.
3. 과제별로 A/B/C를 한 블록으로 두고, 여섯 순열을 무작위 순서로 각각 한 번 실행한다. 과제당 조건별 6회, 총 18회다. 준비 실행은 제외한다. 블록 내 조건을 동시에 돌리지 않는다. 이전 실행과의 간격, 캐시 예열 여부, 모델 세션 압축과 재개 여부를 기록한다. 새 작업 공간은 캐시 초기화를 보장하지 않는다.
4. 각 조건에 동일한 통합 수정 기회를 준다. 충돌 해결과 수정 실행도 비용과 시간에 포함한다. 결과는 동일한 독립 검증과 범위 검토를 통과해야 한다. 실패·시간 초과·비용 데이터 누락도 원래 조건에 남긴다.

## 수집 및 비교

- **완료 시간**은 승인 직후부터 통합 diff와 필수 검증 결과가 검토 가능해질 때까지다. 대기열, 준비, 모델 실행, 통합·재작업, 검증 시간을 함께 기록한다. C의 병렬 구간은 경과 시간으로 계산한다. 사람의 작업 시간은 별도 기록한다.
- **모델 사용량**은 일반 입력·캐시 생성·캐시 읽기·출력을 제공자 정의에 맞춰 수집한다. 부모·하위 실행의 집계 범위를 확인해 중복 합산을 피한다. API 환산액에는 가격표 버전을 붙인다. 구독 사용량과 실제 청구액, 컨테이너·저장 등 인프라 비용을 별도 열에 기록한다. 누락은 미확정으로 남긴다.
- **품질**은 테스트 성공, 요구 범위 충족, 불필요한 diff, 재작업과 결과 수락 여부로 기록한다. 가능한 경우 조건을 가린 상태에서 같은 기준으로 검토한다.
- 실행마다 과제·조건·블록·순서·작업 ID, 세션 수, 실제 동시성, 모델·CLI 버전, diff 해시, 사용량, 시간, 실패 원인과 결과 판정을 남긴다. 조건별 성공률, 성공 건의 비용·시간 중앙값과 범위, 블록별 차이, 실패 비용을 포함한 총비용 ÷ 성공 건수를 보고한다. 성공 건이 0이면 해당 지표는 미정의로 둔다.

같은 품질 기준을 충족하는 조건끼리 비교한다. 병렬화는 반복 비교에서 확인한 시간 절감과 추가 비용을 작업의 기한·예산에 대조해 선택한다. 작은 표본에서 결과가 엇갈리면 컨텍스트 연속성을 기본으로 유지하고 과제 유형을 늘려 다시 측정한다.
