# 이슈 #1 실제 수용 랄프 루프

사용자 지시: 중간에 임의 종료하지 않고 이슈 #1 완료까지 구현·검증·수정을 반복한다. 기존 dirty tree를 보존한다. 새 커밋·push·공개 게시를 추측하지 않는다.

완료 조건은 GitHub 원문의 5개 수용 기준과 R1–R11이다. 최소 24시간의 실제 경과를 합성 시계로 대신하지 않는다. 기존 live version은 51bc6117이며 모델 기능은 비활성이다.

- A1: control 인증이 필요한 모델·자격 주입 없는 단일 원격 boundary probe. 기존 Runner.ensure의 같은 격리 gate를 사용하고 항상 정리한다. 모델 실행·credential 변경·공개 무인증 경로를 만들지 않는다.
- A2: 영속 manifest를 가진 실제 24시간 시험 도구. 한 승인 revision, 고정 모델/도구/기간/예산, 초반 2회 반복 후 예약 대기와 컨테이너 재시작 복원, 회당 실제 Bash/Agent 근거·usage·cache·개입 집계. 모델·외부 실행은 concrete scope 확정 후에만 수행한다. register 응답 유실 때 새 작업을 만들지 않는다.
- A3: 정확한 Fable CLI 모델 ID와 외부 대상/비용 설정 확인. 기존 설정의 안전한 metadata만 조사한다. 자격 원본은 출력하지 않는다. 추측한 대체 모델·AWS target은 사용하지 않는다.
- A4: R7–R9에서 큰 학습 산출물/S3/모델 공개 요구와 현재 1MiB/private commit 범위의 차이를 구체화하고 필요한 구현을 이어간다.

Ruling: 사용자는 AI 조율과 병렬 agent 작업을 승인했다. 현재 tree는 이전 단계와 연속하므로 worktree/commit 이동 없이 파일 소유 범위를 분리한다. 테스트 우선, 집중검사 후 coordinator 전체검사·runtime stamp·독립 최종검토를 실행한다. 운영 배포와 허용된 실제 시험은 확인된 범위로 진행하되 예산·대상·비밀은 추측하지 않는다. 24시간 경과 전 이슈 완료를 주장하지 않는다.

## 사용자 범위 변경

실제24시간 검증·외부 대상·Fable 설정 질문에 사용자가 “이 부분은 실제 프로젝트 진행해 보면서 검증하면 되니까 스킵해줘.”라고 답했다. 실제 프로젝트 실증을 이번 단계에서 제외한다. 이는 검증 통과가 아니라 명시적 이연이다. 실제 모델·외부 자원은 시작하지 않는다. 이번 작업은 로컬 구현·실증 준비 도구·검증 문서로 종료 판단하며 원문 실측 수용 조건의 달성과 구분한다.

## A1 경계 진단

`POST /v1/boundary-diagnostics`는 control 토큰과 8–80자의 영숫자·밑줄·하이픈 `Idempotency-Key` 헤더를 요구한다. 본문과 query는 받지 않는다. 현재 runtime digest와 요청 키로 전용 Runner를 분리하며 같은 키는 재실행하지 않는다. 새 시도는 새 키를 사용한다.

모델 기능이 비활성이어도 기존 `Runner.ensure`의 native 격리 probe만 실행한다. 모델·인증 seed·스케줄러 작업·자격 채택은 실행하지 않는다. 응답은 고정 상태, runtime digest, 종료 확인만 포함한다. 이미지가 준비되지 않았거나 gate가 불확실하면 실패하며 재실행하지 않는다. 30초 대기 제한, 45초 정리 alarm과 종료 실패 시 재정리를 둔다. 플랫폼 API가 응답하지 않을 때 물리적 종료 시각을 보장하는 증거는 아니다.

로컬 모의 검사는 원격 격리 증거를 대신하지 않는다. 실제 클라우드 컨테이너와 모델 호출은 실행하지 않았으며 원격 boundary 검증은 실제 프로젝트 단계로 보류한다.
