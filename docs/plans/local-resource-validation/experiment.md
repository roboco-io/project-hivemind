# 로컬 CPU·메모리·네트워크 제약 검증

[프로젝트 의도](INTENT.md)에 따라 로컬 머신은 작업 제출·승인·진행 조회·결과 검토를 맡는다. Cloudflare 워커 클러스터는 작업별 구현과 검증, 결과 통합과 최종 테스트를 수행한다. AWS ECS는 현재 MVP 완료 후 같은 실험으로 검증한다.

핵심 지표는 **승인부터 최종 통합 테스트 통과까지 걸린 시간**이다. 같은 결과 품질에서 원격 병렬 실행이 납기를 얼마나 줄이는지, 추가 비용과 로컬 응답성 변화가 얼마인지 측정한다.

## 출발점

기존 Terra Medium 실험은 동일 과제의 완료 시간, 모델 요청과 도구 시간, 컨테이너 CPU·메모리를 기록했다. 이 자료는 원격 실행의 기준값과 계측 방법을 제공한다. 당시 실험은 로컬 자원 제약에 따른 동시 완주 한계를 측정하지 않았다. [벤치마크 기록](../../../cloudflare/backend/benchmark/README.md)

클라이언트 재시작 후 같은 원격 통합 결과를 다시 조회한 기록이 있다. 이번 실험에서는 연결이 끊긴 **동안**에도 원격 검증이 진행되는지 확인한다. [클라이언트 재시작 검증](../../verification/2026-11-12-workflow-mcp.md)

작업 묶음, 실행 수와 판정 절차는 [실측 계획](measurement-plan.md)에 정리했다.

## 실험 순서

1. **계측과 기준선.** 같은 커밋의 빌드·테스트를 로컬과 원격에서 실행한다. 작업이 없는 상태와 실행 중인 상태에서 같은 짧은 로컬 명령의 응답 시간을 측정한다. 로컬 호스트와 작업 프로세스 트리의 CPU 시간, 메모리 피크와 스왑, 전송량을 각각 기록한다. 원격은 컨테이너 자원도 별도로 기록한다.
2. **CPU.** 독립적으로 검사할 수 있는 같은 작업 묶음을 양쪽에서 동시 1→2→4개로 늘린다. 사용자 머신의 짧은 명령이 느려지는 정도와 정해진 시간 안에 검증을 통과한 작업 수를 비교한다.
3. **메모리.** 메모리 사용량을 반복 측정할 수 있는 빌드·테스트로 같은 비교를 한다. CPU와 네트워크 조건을 유지하고, 로컬 메모리 압박·스왑·OOM과 완료 여부를 기록한다. 첫 사전 측정에서 정한 안전 범위까지 동시 실행을 늘린다.
4. **네트워크.** 제출 완료 전의 지연과 실행 승인 후의 클라이언트 연결 단절을 별도 시험한다. 재연결 뒤 같은 작업 ID로 결과를 조회하고, 서버 시각의 실행 이벤트·검증 로그로 단절 중 진행을 확인한다. 제출·상태 조회·결과 회수에 걸린 시간과 전송량도 기록한다.
5. **실제 AI 작업.** 앞 단계에서 차이가 확인된 조건에 동일 모델과 랄프 루프를 적용한다. 기준 커밋·지시·완료 기준을 고정하고 독립 작업의 diff·테스트와 최종 통합 테스트를 검증한다. 토큰·재시도·완주당 비용도 기록한다.

비교마다 작업 목록, 소스, 도구 버전, 캐시 조건, 시간 제한과 완료 기준을 고정한다. 한 번에 한 제약을 바꾸고, 같은 작업 묶음을 로컬·원격 순서를 번갈아 각 3회 반복한다. 타임아웃과 실패를 표본에 포함한다. 로컬 유휴 기준과 부하 조건의 실제 측정값, 원격 배치 위치를 함께 기록한다.

## 대규모 작업 비교

공통 계약과 의존성이 있는 개발 목표 하나를 고정한다. 예를 들어 RealWorld의 인증, 게시글, 댓글, 피드 변경을 독립적으로 검증할 수 있는 작업으로 나누고, 마지막에 전체 API 테스트를 실행한다. 모델, 입력 커밋, 작업별 지시, 테스트, 시간 제한을 일치시킨다.

| 실행 조건 | 확인할 차이 |
|---|---|
| 로컬 실행 | 사용자 머신에서 감당할 수 있는 동시 작업 수와 통합 완료 시간 |
| 원격 동시 실행 1개 | 같은 작업 묶음에서 원격 환경의 기본 처리 시간과 비용 |
| 원격 동시 실행 2·4개 | 워커를 늘렸을 때 통합 완료 시간과 완주당 비용의 변화 |

작업을 기다리는 시간, 의존성 때문에 대기한 시간, 작업 실행, 통합 충돌 해결, 재작업과 최종 테스트까지 전체 시간에 포함한다. 각 조건은 독립된 환경에서 시작하고 순서를 교차해 반복한다. 실제 동시 실행 수를 기록하고, 제공자 한도 등으로 계획한 동시 실행 수에 도달하지 못한 경우 이를 결과에 표시한다.

원격 순차 대비 병렬 가속률은 통합 완료 시간의 비율로 계산한다. 로컬 대비 절감 시간과 비용 차이를 함께 표시하고, 완주당 비용에는 실패·재시도·통합까지 포함한다. 클라우드 비용과 모델 비용은 측정 근거를 구분해 기록한다. 비교 실행 전 [실행 위치 선택 기준](selection-criteria.md)에 따라 통합 납기 30% 절감을 초기 목표로 삼는다. 사용자 머신의 응답성 한도와 허용 추가 비용은 작업별로 기록한다.

## 초기 판정 기준

| 가설 | 가설을 지지하는 관측 |
|---|---|
| CPU 제약 완화 | 같은 동시 작업 수에서 원격 사용 중 로컬 응답 시간 p95가 개선되고, 제한 시간 안에 검증을 통과한 작업 수가 유지되거나 늘어난다. |
| 메모리 제약 완화 | 로컬 메모리 압박이나 스왑 증가가 나타나는 동시 작업 수에서도 원격이 같은 결과를 검증하고, 사용자 머신의 메모리 압박이 줄어든다. |
| 연결 단절 내성 | 승인 이후 클라이언트 연결이 끊겨도 원격 검증이 진행되고, 재연결 후 같은 작업 ID로 검증 결과를 회수한다. |
| 대규모 작업의 병렬 처리 | 원격 병렬 실행이 로컬과 원격 순차 실행보다 통합 완료 시간을 줄이고, 같은 검증 기준과 사전 비용 한도를 충족한다. |

판정에 쓸 시간 제한과 로컬 응답 시간의 절대 허용 범위는 첫 기준선 측정과 사용자 요구에 따라 정하고, 비교 실행 전에 기록한다. 선택 기준의 수치들은 검증할 제안값이다. 세 번의 표본에서는 관측 범위와 실패 사례를 함께 공개한다. 로컬 압박이 재현되지 않은 조건에서는 제약 완화 효과를 보류한다.

모델 호출 없는 고정 빌드·테스트의 [로컬 사전 측정](../../verification/2026-11-13-local-resource-pilot.md)을 완료했다. 다음 실행 단위는 CPU 동시 실행 수별 비교다. 원격 반복은 기존 Cloudflare 실행 경로를 사용한다.
