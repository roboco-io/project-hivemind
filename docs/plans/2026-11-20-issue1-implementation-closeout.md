# 이슈 #1 구현 마감과 실제 프로젝트 이관

상태: 이번 bounded 구현 범위의 연결과 전체 검사를 마쳤다. 독립 최종 리뷰는 로컬 후보 범위에서 APPROVED다. 배포 결과는 아래에 기록한다.

## 사용자 결정

이슈 원문의 실제 24시간·외부 제공자·Fable 검증은 사용자가 “실제 프로젝트 진행해 보면서 검증하면 되니까 스킵해줘”라고 지시했다. 이번 단계에서 실제 모델·유료 자원·외부 시스템 작업을 시작하지 않는다. 이 항목을 통과로 표시하거나 실제 24시간이 지난 것으로 계산하지 않는다.

## 이번 보완

- 운영자 전용 모델 없는 원격 격리 검사 API. 기존 native gate와 같은 검사를 쓰고 항상 정리를 시도한다. 인증·모델 실행 기능을 활성화하지 않는다.
- 계획·초안 등록·응답 유실 복구·조회·보고를 위한 실제 프로젝트 인수 도구. 자동 승인을 수행하지 않는다. 공개 API로 증명할 수 없는 Bash/Agent·캐시·무호출 대기는 미검증으로 표시한다.
- HF/GitHub 산출물을 고정 R2 namespace에 등록하는 작업별 경로. 중앙 승인·lease·runtime·현재 revision·프로필·설정 hash를 확인한다. 불변 digest 저장 후 작업/revision/profile별 사용 권한을 기록한다.
- 같은 모델 action 도구에서 파일 등록과 제공자 호출을 연결한다. 새 외부 권한은 추가하지 않으며 업로드 실패·digest 불일치·취소·마감 후에는 제공자 호출을 진행하지 않는다.

## 명시적 한계

HF/GitHub inline 산출물은 총1MiB·32파일·파일당256KiB다. HF는 private 저장소 commit만 지원한다. 대형 모델 LFS, 공개 전환, 범용 S3 작업을 지원한다고 주장하지 않는다. S3는 원문에서 범위 제한 예시이며 별도 S3 연산 계약은 이번 bounded 플랫폼 범위에 없다. 이 범위를 넘어선 Silicon Model Factory 전체 지원은 후속 요구·구현이 필요하다.

모든 실제 환경 수용을 통과했다고 표시하지 않는다. 기존 두 Claude 반복의 실제 근거는 유지하되 신규 장기 실행·Fable·웹 transport·AWS/HF/GitHub·청구·TTL 실증과 구분한다. 기능은 기본 비활성이다.

## 검증

- 루트 `npm run check`: 743개 통과, 실패·건너뜀 0개.
- 백엔드 타입 검사와 전체 검사: 649개 통과, 실패·건너뜀 0개.
- AWS guard 타입 검사, CDK 검사3개, Python 검사20개 통과. 실제 AWS 호출 없음.
- runtime stamp/check, linux/amd64 이미지 빌드, 모델 없는 로컬 부트스트랩, Wrangler 배포 dry-run 통과.
- 두 차례 독립 코드 경계 검토에서 재현 가능한 추가 P1/P2를 발견하지 못했다. 최종 패킷 리뷰는 별도로 기록한다.
- 기존 취소 검사3곳의 50ms 시간 경쟁을 진입·해제 gate로 교체했다. reporter 해제 전 취소가 거절 결과를 내는지 확인한다. 제품 코드의 취소 정책을 완화하지 않았다.
- 기존 사용자 변경인 `docs/plans/local-resource-validation/INTENT.md` EOF 공백은 기준 사본과 동일하며 보존했다. 해당 경로를 제외한 `git diff --check`는 통과했다.

새로운 실제 원격 probe는 실행하지 않는다. 이전 로컬 QEMU 샌드박스 실패는 해소된 것으로 표시하지 않으며 실제 프로젝트 활성화 전 원격 gate를 유지한다.

## 동결 후보와 판정

- runtime digest: `ea244c8537dd849c5c6ac0ed0b2cab586c7a892864f725dfeaee54da71394d91`
- 로컬 image index: `sha256:6698779250f1cbeb9f4ffd448b0cf9b727bf2afbb0da6acc3fdcc49295b2cdda`
- Worker dry-run bundle SHA-256: `56695d5bbc7171d898bf8788705084864a2e6190062a84dea787946d6672ad80`
- 소스257개 hash를 동결했다. 전체 검사 뒤 제품 소스 변동은 없다. 마지막 변경은 취소 검사의 결정적 oracle 보강이며 해당 최종 백엔드 전체649개가 통과했다.
- 새 독립 최종 검토자는 `FINAL CURRENT` 패킷의743/649 근거와 새 게시·진단 경계를 읽고 **APPROVED**로 판정했다. 실제 원격 격리·외부 제공자·24시간 운영이나 Silicon Model Factory 전체 지원의 승인이 아니다.

따라서 이번 사용자 조정 범위의 bounded 구현을 완료로 판정한다. 원문 이슈의 실제5개 수용 기준은 실제 프로젝트에서 검증할 항목으로 남긴다. GitHub 이슈를 실제 수용 통과로 표시하거나 자동으로 닫지 않는다. 작업은 미커밋 상태로 보존한다.

배포 시 첫 시도는 Worker 업로드 뒤 DO-managed Container 설정 적용이 완료되지 않아 종료 코드1을 반환했다. 도구의 동일 명령 재시도 안내에 따라 같은 동결 후보로 재시도하며 최종 결과를 따로 확인한다. 이미지 등록만으로 배포 완료를 주장하지 않는다.

## 최종 배포

최초 두 배포는 Worker 업로드 이후 Container 설정 적용 단계에서 실패했다. 같은 소스·설정으로 실행한 세 번째 CLI 배포는 정상 종료했으며 version `3b5002f4-a596-4400-a208-51ee675a96fa`를 반환했다. 원인은 확정하지 않았으며 실패 기록을 성공 로그로 덮어쓰지 않았다. 저장소·설치된 Wrangler 코드를 변경하거나 검증을 우회하지 않았다. 진단 래퍼는 같은 CLI main을 호출하고 오류가 있을 때 cause 범주만 기록하도록 준비했으며, 최종 실행은 오류 없이 완료됐다.

registry image manifest는 `sha256:6af3b06888b8ed0ff507493f1f952f19422c9b3523cad786fc326308dd0238b9`다. 앞서 기록한 로컬 index digest와 구분한다. 새 기능은 비활성으로 유지하며 실제 모델·AWS/HF/GitHub·유료 컨테이너 probe를 실행하지 않았다.

배포 후 확인 시각 `2026-11-20T07:16:22.335Z`: runtime hash 일치, 기존338개 종료 작업 보존, 실행 중0, 자격 점유·격리0, readiness false를 확인했다. 새 경로는 무인증 boundary POST401, 운영자 boundary GET405, 운영자의 worker artifact POST401을 반환했다. 이 검사는 컨테이너·모델 실행 없이 인증 경계만 확인한 것이다.
