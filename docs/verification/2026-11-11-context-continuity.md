# 컨텍스트 연속성 실험 결과

2026-11-11 KST. 두 과제 모두 단일 세션의 비용과 완료 시간 중앙값이 가장 낮았다. 독립 분할은 단일 세션 대비 API 환산 비용이 2.56~2.73배, 완료 시간이 1.55~1.63배였다. 전체 36회 중 35회가 필수 테스트를 통과했다.

## 조건과 측정

[실험 설계](../plans/2026-11-11-context-continuity-experiment.md)의 A/B/C를 두 소형 JavaScript 과제에서 각각 6회씩 실행했다. 공유 규칙 과제는 정수 범위 함수 4개, 독립 기능 과제는 slug·중복 제거·중앙값·문자열 패딩 함수다. 각각 사전에 정의한 테스트 12개가 기준 커밋에서 모두 실패한다.

| 과제 | 고정 시작 커밋 | B의 묶음 |
|---|---|---|
| 공유 규칙 | `bc4d37fa54a37d6536999ecc16e0f4a6d1295275` | clamp·wrap / steps·width |
| 독립 기능 | `95ab9dee16e5e7dcc94d3ca8bfa21207527fd6bc` | slug·unique / median·pad |

로컬 macOS arm64에서 Claude Code 2.1.321, Node.js 24.14.0을 사용했다. 모든 세션의 응답 모델 ID는 `claude-haiku-4-5-20251001`이었다. 같은 로그인과 Read·Edit 권한, low effort 설정을 적용했다. 같은 인증의 작업을 직렬화하는 Cloudflare 대신 로컬 CLI를 선택해 C의 동시 실행을 측정했다. C는 독립 복제본 4개에서 최대 2세션을 동시에 실행하고 파일 변경을 정해진 순서로 통합했다. B는 같은 작업 공간에서 세션 두 개를 순차 실행했다. A는 세션 하나를 사용했다.

과제별 여섯 블록에 A/B/C 순열을 한 번씩 배치했다. 모델 세션은 총 84개이며 준비 실행은 제외했다. 캐시를 초기화하지 않았고, 직전 실행의 마지막 세션과 다음 실행의 첫 세션 사이 간격은 최대 0.414초였다. 세션 재개나 압축 이벤트는 관측되지 않았다. 각 실행의 시간은 복제부터 최종 diff와 독립 테스트 수집까지다. 최종 검증 이후 모델 재시도는 세 조건 모두 0회다.

## 판단

C의 성공 실행에서 CLI 프로세스가 겹친 시간의 중앙값은 공유 규칙 19.82초, 독립 기능 20.90초였다. C는 두 과제에서 B보다 빨랐지만 A보다 느렸다. 비용 차이에는 캐시 쓰기뿐 아니라 캐시 읽기와 출력 증가도 포함된다. 이 비교는 세 실행 방식 전체의 차이를 보여 준다. 캐시와 병렬성의 개별 효과는 분리하지 않았다.

이 범위에서는 **단일 세션을 기본으로 유지**한다. 모델과 과제는 각각 하나와 두 개로 한정됐고, 변경이 작고 파일 충돌이 없는 과제다. 장시간 작업이나 실제 Cloudflare 실행에서의 손익분기는 별도 비교가 필요하다.

## 증거와 재현

[실행별 기록](2026-11-11-context-continuity-results.json)에 순서·diff 해시·테스트·세션 시간·사용량을 담았다. 초기 집계기가 Node의 기본 spec 출력 형식을 읽지 못했다. 보존된 테스트 출력과 종료 코드를 다시 집계해 수정했으며 모델 실행을 반복하지 않았다. 첫 블록에는 로컬 저장소 회귀 검사도 함께 실행됐으므로 타이밍 해석에 이 조건을 고려한다.

```sh
python3 scripts/experiments/context_continuity.py full .hivemind/context-exp-replay
python3 scripts/experiments/summarize_context_continuity.py .hivemind/context-exp-replay
```

재현 명령은 실제 모델 세션 84개를 시작한다. 원본 로그와 작업 복제본은 지정한 로컬 경로에 저장한다.
