# 2026-11-27 검증 보고서 — HIVEMIND 부트스트랩

이 문서는 부트스트랩 명령(`npm run bootstrap`)의 구현 내용과 확인 결과를 기록한다. 실 AWS 확인은 2026-11-27에 계정 `<AWS_ACCOUNT_ID>`, 프로필 `roboco`에서 했다.

## 1. 무엇을 만들었는가

부트스트랩은 HIVEMIND의 AWS 단일 경로를 쓸 수 있는 상태로 만드는 설치 명령이다. 이전에는 같은 일이 스크립트 7개에 흩어져 있었고, 실행 순서를 사람이 알아야 했다. 특히 DSQL의 제한된 DB 역할을 만들기 전에 제한된 설정으로 Hub를 배포하면 서비스가 DB에 접속하지 못한다. 부트스트랩은 이 순서를 명령 하나에 넣었다.

단계는 사전 점검, CDK 부트스트랩, Hub 첫 배포, 컨테이너 이미지, Spoke 배포, DSQL 테이블과 제한된 DB 역할, Hub 최종 배포, 인증 등록 3종, 로컬 MCP 클라이언트 설정, 동작 확인이다. 각 단계는 먼저 현재 상태를 확인하고 빠진 것만 수행한다.

결정된 동작은 세 가지다. 형태는 CLI 명령과 스킬(`hivemind-bootstrap`) 둘 다 제공한다. 기본 범위는 서울 Hub이고 Spoke는 `--spokes`로 고른다. 주어지지 않은 인증 값은 건너뛰고, 끝에 무엇이 빠졌고 어떤 기능이 동작하지 않는지 보고한다.

## 2. 자동 검증

`npm run check`는 1,279건이 모두 통과했다. `tests/bootstrap.test.ts`(6건)는 AWS·Docker·파일 접근을 가짜로 바꿔 다음을 확인한다.

- 빈 계정에서 Hub 첫 배포(관리자 접속 설정), 이미지 푸시, DSQL 역할 적용, Hub 최종 배포(제한된 설정)가 이 순서로 실행된다.
- 다시 실행하면 이미 있는 리소스를 건드리지 않고, 이미 배포된 Spoke가 Hub 설정에 계속 들어간다.
- 주어진 인증 값은 등록되고, 잘못된 인증 값은 그 단계만 실패한다.
- 리소스 단계가 실패하면 뒤의 리소스 단계가 실행되지 않고, 제한된 설정의 Hub 배포도 실행되지 않는다.
- `--dry-run`은 읽기 전용 점검 외에 아무 명령도 실행하지 않는다.
- 운영자 토큰, ECR 비밀번호, 모델 인증 값, Hugging Face 토큰이 명령줄 인자와 보고서에 나오지 않는다.

`tests/claude-skill.test.ts`는 스킬 문서가 승인 규칙과 비밀 취급 규칙을 담고 있는지, 스킬이 설명하는 옵션과 CLI의 옵션이 같은지 확인한다.

## 3. 실 AWS 확인

이미 구성이 끝난 운영 계정에서 실행했다. 따라서 이 확인이 보여 주는 것은 **반복 실행이 안전하다**는 것이다.

| 단계 | 결과 |
|---|---|
| 사전 점검 | 계정 `<AWS_ACCOUNT_ID>`, Docker와 CDK 사용 가능 |
| CDK 부트스트랩, Hub 첫 배포, 컨테이너 이미지, Spoke 배포 | 모두 "이미 됨". 새로 만들거나 바꾼 것 없음 |
| DSQL 테이블과 제한된 DB 역할 | 다시 적용됨. 결과는 이전과 같음 |
| Hub 최종 배포 | 실행됨. Spoke 4개 리전이 설정에 유지됨 |
| 모델 구독 인증, GitHub App, Hugging Face 토큰 | 모두 "이미 됨" (Codex 자격, App 5939785와 저장소 2개, 토큰 등록됨) |
| 로컬 MCP 클라이언트 설정 | 운영자 토큰 파일(권한 600)과 `.mcp.json`, `.codex/config.toml` 작성 |
| 동작 확인 | 세 저장소 모두 `aurora-dsql`로 응답. Control Plane은 다시 `desiredCount 0` |

실행 뒤 Control Plane 역할의 DSQL 권한은 `dsql:DbConnect` 하나로 유지됐다. 부트스트랩이 서비스를 관리자 접속으로 되돌리지 않았다는 뜻이다. Spoke 4개도 `--spokes`를 주지 않았는데 Hub 설정에 남았다.

`--dry-run`도 같은 계정에서 실행했고, 위 표와 같은 판단을 보고했으며 아무것도 바꾸지 않았다.

### 첫 실행에서 드러난 문제와 수정

첫 실제 실행에서 로컬 MCP 클라이언트 설정 단계가 실패했다. 원인은 같은 날 `.mcp.json`의 `hivemind` 항목을 설치 스크립트를 거치지 않고 손으로 고친 것이었다. 설치 스크립트는 관리 대상 항목이 밖에서 바뀌면 덮어쓰지 않고 거절한다. 이 거절은 의도된 동작이다. 손으로 고친 부분을 되돌린 뒤 다시 실행하자 통과했다.

이 실패에서 부트스트랩의 문제 두 가지가 드러나 고쳤다. 설치 스크립트의 오류 원문이 보고에 나오지 않고 "Command failed"만 나왔다. 그리고 로컬 설정 실패가 뒤의 동작 확인까지 막았다. 로컬 설정은 이 컴퓨터의 편의 설정이고 클라우드 구성과 무관하므로, 실패해도 동작 확인은 진행하도록 바꿨다.

## 4. 한계와 미검증 항목

- **빈 계정에서의 첫 설치는 실 AWS에서 실행하지 않았다.** 새 계정이 없어서다. 리소스를 처음 만드는 경로(CDK 부트스트랩, Hub 첫 배포, 이미지 첫 빌드, Spoke 신규 배포)는 단위 테스트로만 확인했다. 개별 스크립트는 2026-11-26과 11-27에 이 계정에서 각각 실행해 동작을 확인했지만, 부트스트랩이 빈 상태에서 그것들을 이어 실행한 적은 없다.
- **인증 값을 새로 등록하는 경로도 부트스트랩을 통해서는 실행하지 않았다.** 세 인증 값이 이미 등록되어 있어 "이미 됨"으로 지나갔다.
- **부트스트랩은 리소스를 지우지 않는다.** 제거와 Spoke 삭제 기능은 없다.
- **이미지 단계는 태그 유무만 본다.** ECR에 `latest` 태그가 있으면 코드가 바뀌었어도 다시 빌드하지 않는다. 코드 변경을 반영하려면 `--rebuild-images`를 줘야 한다.
- **Hub 최종 배포와 DSQL 역할 적용은 매번 실행된다.** 둘 다 결과가 같도록 만들어져 있지만, 변경이 없어도 실행 시간이 든다.
