## 후속: 로그인 후에도 발생한 인증 오류 수정

사용자가 공식 구독 로그인을 완료했으나 두 번째 로컬 시도에서도 같은 오류가 발생했다. 일반 환경의 `claude auth status`는 로그인됨, 실험의 제한 환경은 로그인 안 됨으로 달랐다. 환경변수를 하나씩 복원하는 읽기 전용 검사에서 `USER`만 추가하면 구독 인증을 찾았다. 실행기의 환경 정리가 macOS Keychain 계정 조회에 필요한 사용자 이름을 제거한 것이 확인된 원인이다. 오류 문구만으로 사용자 로그인 자체의 만료를 단정할 수 없었다.

모델 프로세스에 운영체제 `userInfo().username`을 전달하도록 수정했다. API 키 등의 환경변수는 계속 제외한다. 실제 Claude Opus 5.5 짧은 요청이 성공했고 모델 식별자와 사용량을 확인했다. 첫 두 실패 시도는 `suite`, `suite-v2`에 보존하며 `suite-v3`에서 본실험을 재개했다. 인증 확인용 짧은 요청은 본실험 납기에 포함하지 않는다.

## 후속: 모델 자체 검증과 서비스 검증 분리

`suite-v3` 첫 로컬 목표는 187.872초에 통합 성공했다. 원격 순차 목표도 1,338.924초에 성공했으나 Claude가 도구 sandbox에서 npm 설치를 시도했다. sandbox의 도구 네트워크 정책은 이를 허용하지 않았으며, 별도 compute 컨테이너의 서비스 수용 검사는 통과했다. 작업 지시의 직접 검증 요구가 실행 경계와 충돌했다.

원격 Claude의 실제 첫 native 턴은 1,078.105초, 이후 랄프 검증 대기는 약 25.381초다. 기존 `process.durationMs`는 이 대기를 포함하므로 순수 모델 시간이라고 표현하면 안 된다. 마지막 Bash 시작 이후 883.081초 동안 완료 시각 근거가 없고, 이 전체를 npm이나 모델 대기로 확정할 수 없다.

동일 문제를 반복하는 원격 병렬 목표의 Claude를 중앙 취소 경로로 중지했다. 종료·컨테이너 정지·인증 경계 정상 상태를 확인했다. 이 실행은 운영자 중단으로 보존하며 성공 시간 통계에 넣지 않는다. 이후 비교는 모든 환경에서 모델에 코드 수정만 맡기고, 설치·빌드·수용 검사를 서비스가 수행하는 지시로 통일한다. 기존 sandbox를 완화하지 않는다.
