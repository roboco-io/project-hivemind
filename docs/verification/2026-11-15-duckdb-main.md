# DuckDB 빌드 본실험 실행 기록

원격 C1 확인 실행에서 이전 Cloudflare 테스트 목록 SHA-256을 재현했다. 로컬과 원격의 테스트 이름 16개는 모두 같았고 열거 순서만 달랐다. 로컬은 select_star_replace부터, 원격은 coalesce_error부터 나열했다. 이름을 정렬하면 두 목록이 일치했다. 본실험은 동일한 [Projection 테스트 목록](../../cloudflare/backend/scripts/duckdb-pilot/projection-tests.txt)을 양쪽의 Catch 실행기에 전달한다. 실행 순서는 이름순으로 고정한다. 빌드마다 열거된 목록의 집합과 실제 성공한 테스트 개수도 검사한다.

세 블록에 로컬 2워커×컴파일 동시성 5, 로컬 4×4, Cloudflare standard-4 1×4·2×4·4×4를 한 번씩 넣고 고정 시드로 순서를 정했다. 한 번에 한 조건만 실행한다. 모든 조건은 DuckDB v1.4.2의 동일 C1–C4 구성과 새 빌드 디렉터리를 사용한다. 원격 작업은 해시가 고정된 R2 소스를 복원한다. 로컬은 미리 준비한 동일 소스 트리를 사용한다.

로컬 공통 소스 준비는 측정 이전에 끝났고 원격 복원은 승인 이후 워커별로 기록한다. 원격 마지막 통합은 네 검사의 성공을 모으는 집계 작업이다. 추가 컴파일은 없다. 승인 전에 고정한 $30 추정 기준에 대해 원격의 36개 빌드·9개 집계 작업의 제한 시간을 전부 사용하고 CPU를 최대로 사용하는 컨테이너 환산 시나리오는 약 $14.56이다. 운영 예비비 $10을 추가해 실행을 시작했다. 실제 청구는 계정 사용량과 별도 서비스 비용을 반영한다. 실행 기록은 `.hivemind/duckdb-pilot/main-matrix/`의 manifest, 조건별 근거, 비용 조회 및 보고서에 남긴다. 부분 표본에서 조건의 우위를 판정하지 않는다.

[조건별 측정 표](2026-11-15-duckdb-main-results.md)는 실행기가 종료되면 기록된 결과와 비용 조회로 갱신한다.

첫 로컬 4×4 묶음에서는 C1·C2가 통과했고 C3·C4는 60분 제한에 도달했다. Node 응답 p95는 302.8ms, 호스트 CPU busy p95는 100%였고 메모리 상태는 warning이었다. 시간 초과 프로세스의 CPU 합계는 확보하지 못했다. 측정 자료만으로 느려진 원인을 특정할 수 없다. 이 묶음을 실패로 보존했다. 재개할 때 관측이 확보된 실패 뒤에도 다음 조건을 실행하도록 제어기를 수정했고, 전원 연결 상태에서 절전 방지 범위를 남은 실행으로 한정했다. 기존 조건, 순서, 작업 제한은 그대로 적용했다.


15묶음이 모두 종료됐고 14묶음이 완주했다. 로컬 2×5는 3/3 완주, 1,227.807초 중앙값으로 이번 비교의 로컬 기준이다. 로컬 4×4는 성공 두 건의 중앙값이 1,215.793초였으나 1건이 시간 초과였다. Cloudflare 4×4는 3/3 완주하며 Cloudflare 순차보다 약 2.61배 빨랐고, 로컬 2×5보다 약 15.3% 오래 걸렸다. OS·컴파일러·하드웨어가 다른 운영 설정 비교다.

Cloudflare의 36개 빌드 워커는 모두 같은 16개 테스트 이름과 고정 목록 SHA를 보고했다. 원격 워커의 기록된 CPU 스로틀링은 0이었다. 로컬 2×5의 Node 응답 p95 중앙값은 약 126ms였다. 메모리 표는 로컬 전체 작업 트리의 RSS 표본 피크와 원격 단일 워커의 cgroup 피크를 구분한다.

Cloudflare Analytics는 45개 중 39개 컨테이너에 대해 총 $3.78595를 보고했다. 빠진 6개는 모두 최종 집계 컨테이너다. 각 집계의 생성부터 종료까지 걸린 시간에 standard-4의 최대 CPU·메모리·디스크 요율을 적용해 보완하면 추정 합계는 약 $3.791이다. 완주당 추정은 1워커 $0.409, 2워커 $0.425, 4워커 $0.430이다. 이 보완 산식에는 누락 집계의 전송 비용이 없으며, R2·Workers·Durable Objects 및 로컬 전력은 별도다.
