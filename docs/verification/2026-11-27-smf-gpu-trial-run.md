# 2026-11-27 검증 보고서 — Silicon Model Factory의 GPU 시험 실행

이 문서는 외부 프로젝트 Silicon Model Factory(`roboco-io/silicon-model-factory`, 이하 SMF)가 HIVEMIND의 GPU 스팟 학습 기능을 실제로 쓴 첫 실행의 기록이다. 목적은 HIVEMIND의 학습 경로가 실제 모델 학습에서 동작하는지 확인하는 것이었다. 지금까지의 실증은 `t4g.nano` 인스턴스와 파일 1개짜리 산출물로만 이루어졌다.

실행은 2026-11-27에 계정 `<AWS_ACCOUNT_ID>`에서 했다. 운영자 조작은 Claude Code 세션에 연결된 HIVEMIND MCP 도구로 했다. SMF 쪽 기록은 그 저장소의 `logs/stage2-trial-run.md`에 있다.

## 1. 결과

세 번째 시도에서 전체 경로가 통과했다.

| 단계 | 결과 |
|---|---|
| Control Plane 기동 (`hivemind_control_plane_start`) | 52초. 실제 MCP 클라이언트 연결에서 처음 호출했다 |
| 작업 등록과 학습 승인 (`hivemind_mf_create`, `hivemind_mf_approve_training`) | `g4dn.xlarge` 스팟이 us-east-2a에 기동 |
| 고정 입력 전달 | 인스턴스가 8개 파일(약 64MB)을 내려받아 SHA-256을 확인 |
| 학습 | Tesla T4에서 640쌍, 10 스텝, 90.6초 |
| 산출물과 영수증 | 14개 파일(약 548MB)을 올리고 영수증 작성. Control Plane이 영수증을 받아들여 `evaluating`으로 전환 |
| 독립 검증기 (`hivemind_mf_dispatch_verifier`) | 약 50초 만에 14개 파일의 해시를 확인하고 검사 통과. `attestationSource: independent_verifier` |
| 최종 상태 | `awaiting_release_approval` |
| 종료 후 | 실행 중인 관리 대상 인스턴스 0대, Control Plane `desiredCount 0` |

이 실행으로 이전에 미검증이던 항목 세 가지를 확인했다. GPU 인스턴스 유형으로 학습이 돈다. 실제 스팟 용량 부족이 발생했을 때 Control Plane이 리전의 모든 서브넷을 차례로 시도한다. 독립 검증기가 수백 MB의 산출물을 검증한다.

## 2. 드러난 결함과 조치

### 고친 것

**영수증 해시의 파일 정렬 (커밋 `c774a53`).** Control Plane은 산출물 목록을 `localeCompare`로 정렬해 해시했다. 인스턴스는 자기 언어로 해시를 계산하므로 보통 바이트 순서로 정렬한다. 두 순서는 대소문자나 문장부호가 섞이면 다르다. 바이트 순서에서는 `model/README.md`가 `model/config.json`보다 앞이고 로케일 순서에서는 뒤다. 실제 모델 산출물에서는 영수증이 거절됐을 결함이다. 정렬을 코드 단위 순서로 바꾸고, 연동 가이드에 영수증 형식과 계산 규칙을 적었다. 실행 전에 코드에서 찾았고, 실행에서 14개 파일의 해시가 일치하는 것을 확인했다.

**용량 부족 시 실패 기록 누락 (커밋 `fd23e25`).** 첫 시도에서 `g6.xlarge`가 us-east-2의 세 가용 영역 모두에서 `InsufficientInstanceCapacity`로 거절됐다. Control Plane은 세 오류 메시지를 이어 붙여 실패 사유로 기록하려 했는데, 길이가 1,000자 제한을 넘어 기록 함수가 예외를 냈다. 작업은 `failed`가 되지 못하고 예산 450,000 마이크로달러를 예약한 채 `training_queued`에 남았다. 운영자에게는 일반 오류 문구만 보였고 작업의 진단 기록은 비어 있었다. 이제 실패 사유는 길면 잘라서 기록하고, 시도한 위치와 AWS 오류 코드만 사유에 적는다. 전체 메시지는 배치 시도 로그 이벤트에 600자까지 남긴다. 이 수정은 단위 테스트로 확인했고, 실 AWS에서 용량 부족을 다시 만나지는 못했다.

**MCP 등록 도구의 후보 리전 (커밋 `fd23e25`).** `hivemind_mf_create`에 `candidateRegions`와 `regionOverrides`가 없어서, MCP로는 다른 리전으로 넘어가는 작업을 등록할 수 없었다. 두 항목을 추가했다. 실 AWS에서 호출하지는 않았다.

### 고치지 않은 것

**정산 시간이 실제 실행 시간보다 길다.** Control Plane은 인스턴스가 종료한 시각이 아니라 종료를 알아챈 시각까지를 실행 시간으로 센다. 점검 주기가 5분이어서 차이가 크다. 두 번째 시도의 인스턴스는 약 60초 실행됐는데 328초로 정산됐고, 세 번째는 약 390초 실행됐는데 668초로 정산됐다. 정산은 상한가 기준 추정이므로 실제 청구보다 적게 잡히지는 않지만, 원장의 값이 실제와 수 배 다르다. EC2가 돌려주는 상태 전이 시각을 쓰면 줄일 수 있다.

**끝난 작업을 최대 5분 뒤에 알아챈다.** 인스턴스가 영수증을 쓰고 종료해도 작업은 다음 점검까지 `training_running`이다. 운영자가 점검을 당길 MCP 도구가 없다. API에는 `POST /api/model-factory/jobs/:id/wake`가 있다.

**루트 볼륨 크기를 정할 수 없다.** 학습 작업 계약에 볼륨 항목이 없어 AMI의 기본값(이번 AMI는 30GB)을 쓴다. 체크포인트를 여러 개 쓰는 학습에서는 부족할 수 있다.

**용량 부족을 사전에 알 수 없다.** 작업 등록 도구는 스팟 배치 점수를 보여 주지 않는다. 이번에는 AWS CLI로 점수를 조회해 인스턴스 유형을 바꿨다.

## 3. 비용

HIVEMIND 원장의 정산은 두 번째 시도 36,445 마이크로달러, 세 번째 시도 74,223 마이크로달러다. 합계는 약 0.11 USD다. 이 값은 상한가 0.40 USD/시간과 위에 적은 부풀려진 실행 시간으로 계산한 추정이다. Control Plane과 검증기의 Fargate 비용은 원장에 들어 있지 않다. 실제 청구액은 확인하지 않았다.

## 4. 미검증 항목

- 학습 분할 전체를 쓰는 본 학습. 이번은 640쌍, 10 스텝이다.
- 스팟 중단과 체크포인트에서의 재개.
- 다른 리전으로의 폴백. 이번 작업은 리전을 하나만 적었다.
- Hugging Face 공개 단계. 이번 작업은 `s3_artifact_only`다.
- 유휴 자동 종료가 진행 중인 학습 때문에 미뤄지는 경로. 학습이 15분보다 짧았고 그동안 도구 호출이 이어졌다.
