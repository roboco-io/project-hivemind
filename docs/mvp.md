# MVP 범위

## 제품 목표

한 사람이 중앙에서 작업을 등록하고 여러 원격 AI 워커에 분배한다.
사람은 같은 관제실에서 진행 상황, 실패, 승인 대기, 비용과 Git 변경 제안을 이해하고 통제한다.

## 이번 최소 골격

| 포함 항목 | 검증할 행동 |
|---|---|
| 작업 등록 | 제목·완료 조건·예산을 저장하고 실행 승인 상태로 시작 |
| 실행 승인 | 사람 승인 전에는 워커가 작업을 가져가지 못함 |
| 중앙 분배 | 여러 워커가 서로 다른 승인 작업을 가져감 |
| 실행 권한 | 중복 claim을 막고 heartbeat·만료·취소를 처리 |
| 결과 검토 | 합성 diff·요약·모의 비용을 표시하고 수락·반려를 기록 |
| 이력 | 상태와 이벤트가 같은 트랜잭션으로 저장되고 재시작 후 유지 |
| 역할 구분 | 워커는 사람의 결정을 대신 기록할 수 없음 |
| 개발 환경 | 로컬 API·UI·워커를 시작하고 자동 테스트를 실행 |

현재는 mock/local 조합만 지원한다. 실제 모델·저장소·클라우드를 연결한 제품 MVP와 구분한다.
초기 골격의 완료 조건은 [초기 개발 계획](plans/2026-11-09-bootstrap.md)에 있다.

## 제품 MVP까지 추가할 범위

1. 사용자가 지정한 저장소와 고정 base commit으로 작업 공간을 격리한다.
2. Codex 실행 어댑터 하나를 실제로 연결하고 도구 승인·로그·오류를 중앙 이벤트로 변환한다.
3. 실제 Git diff, base/head commit, 테스트 결과와 사용량 근거를 실행에 연결한다.
4. ECS에서 작업당 컨테이너를 시작·중지하고 유실·중복 결과를 처리한다.
5. 실행 시간과 사용량 한도, 취소 전파, 비밀 주입과 사용자 인증을 구현한다.
6. 최소 두 워커의 병렬 작업을 같은 관제실에서 확인한다.

실행 전 승인과 결과 수락은 유지한다. 승인 없는 push·merge·deploy를 추가하지 않는다.
중앙 계획은 우선 사람이 검토한 작업 목록으로 시작하고, 자동 분해는 후속 확장으로 둔다.

## 제품 MVP 수용 시나리오

- 사람이 지정한 저장소에서 두 작업을 승인하면 서로 격리된 워커가 실행한다.
- UI에서 각 실행의 제공자, base commit, 로그, 테스트 결과와 변경 diff를 확인한다.
- 연결이 끊긴 워커와 취소된 실행은 결과를 덮어쓰지 못한다.
- 재시작 후 승인 대기와 실행 기록을 복원한다.
- 비용은 추정과 실측을 구분하고, 미수집 사용량을 0달러로 확정하지 않는다.
- 결과 수락만으로 외부 저장소 변경이나 배포가 발생하지 않는다.

## 후속 확장

Claude Code 어댑터, ChatGPT MCP UI, Cloudflare Containers,
모델별 비용·능력 라우팅, 자동 작업 분해, 작업 의존성 DAG,
다중 사용자와 조직별 권한은 단계적으로 추가한다.
결제, 마켓플레이스와 공개 서비스 운영은 이번 범위에 포함하지 않는다.
