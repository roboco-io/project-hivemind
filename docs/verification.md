# Project HIVEMIND 검증

## 실제 Codex / worktree 추가 검증

검증일: 2026-11-09. Node.js 24.14.0에서 `npm run check`로
타입 검사·빌드 성공, 자동 테스트 47개 통과, 실패·생략 0개를 확인했다.
구현 범위와 실행 방법은 README와 ADR 0006을 참조한다.

- API·워커·실제 Git worktree·fixture CLI를 HTTP로 연결해 테스트 성공/실패 결과를 검증했다.
- dirty 원본 체크아웃과 index 보존, 새 파일·삭제·binary diff, 빈 diff를 확인했다.
- Codex/준비 명령/테스트 실패, 시간 초과, 취소, 종료 신호, SIGTERM을 무시하는 자식 종료를 검증했다.
- 관제 토큰·추론 인증이 준비 명령과 테스트 환경에 전달되지 않음을 확인했다.
- 테스트 argv를 작업에 복사해 고정하고, 서버 설정 변경·재시작에도 기존 승인 명령을 유지함을 확인했다.
- 초기 연동 검증에서는 실제 Codex CLI 0.166.0과 기존 ChatGPT 로그인을 사용한 호출 1회를 수행했다.
  임시 저장소에서 잘못된 덧셈 함수를 별도 worktree에서 수정했고,
  실제 diff와 테스트 2개 통과·종료 코드 0·stdout을 저장했다.
- 원본 코드, 기존 수정 파일과 index가 보존됨을 확인했다.
- 브라우저에서 실제 결과와 미확정 비용을 확인하고 사람이 결과를 수락했다.
  서버 재시작 뒤 diff·테스트 출력·수락 상태가 복원됨을 확인했다.
- 추가 브라우저 검증에서 실패 결과의 승인 불가, HTML 비실행,
  조회 중 입력·포커스 유지, 390px 화면의 가로 넘침 없음을 확인했다.

실제 Codex 금액은 수집하지 못했으므로 `actualCostMicros=null`로 저장한다.
토큰 사용량만 저장했고 임의 단가로 금액을 추정하지 않았다.
이번 worktree는 파일 변경 격리다. 테스트 명령은 신뢰하는 저장소의 코드를 호스트에서 실행한다.
ECS/Cloudflare, Claude/MCP, Windows 프로세스 그룹 정리는 검증하지 않았다.

## 실제 프로젝트 README 작업 시연

2026-11-09에 실제 Codex 호출 1회를 추가로 수행했다.
관제 화면에서 README 개선 작업을 등록하고 실행 승인한 뒤,
현재 프로젝트의 고정 커밋에서 만든 worktree로 실행했다.
Codex가 변경한 추적 파일은 README.md 하나였으며 원본 README는 검토 전까지 변경되지 않았다.
워커의 `npm ci --ignore-scripts --no-audit --no-fund`와 `npm run check`가 성공했고,
실제 테스트 47개 통과·실패 0개·종료 코드 0을 관제 화면에서 확인했다.
base와 실행 후 HEAD가 동일함을 확인하고 결과를 수락한 다음,
검토한 README patch와 실제 화면 캡처를 원본 저장소에 반영했다.
README의 결과 캡처에서는 개인 로컬 경로만 숨겼다.

## 꿀벌 로고 적용 검증

README와 관제 헤더에는 심플한 꿀벌과 손글씨를 결합한 로고를 사용하고,
브라우저 아이콘에는 승인한 심플 꿀벌의 투명 PNG를 사용한다.
로컬 API가 두 PNG를 원본과 같은 바이너리로 제공함을 확인했다.
브라우저에서 데스크톱 높이 70px·모바일 높이 58px 로고 표시를 확인했고,
390px 화면에서 가로 넘침과 콘솔 오류가 없었다.
컨테이너 이미지를 다시 빌드하고 두 이미지 경로의 응답도 확인했다.

## 초기 모의 골격 검증 기록

검증일: 2026-11-09. 아래 기록은 로컬 초기 골격의 검증 결과다.
이 초기 모의 검증 단계에서는 외부 모델 호출과 클라우드 배포를 수행하지 않았다.
공개 소스 저장소는 [roboco-io/project-hivemind](https://github.com/roboco-io/project-hivemind)다.

### 초기 자동 검증

Node.js 24.14.0에서 `npm run check`를 실행했다.
타입 검사와 빌드 성공, 자동 테스트 17개 통과, 실패·생략 0개.
전달용 압축본을 별도 폴더에 풀고 `npm ci`와 `npm run check`로 설치·검증도 확인했다.
최종 코드 검토에서 발견한 트랜잭션 대기 중 lease 만료 문제를 수정하고 회귀 검증을 추가했다.

- 실행 승인과 결과 수락의 분리, 승인 이벤트와 사유 보존.
- 한 작업의 중복 claim 방지, 잘못된 lease 거절, 만료·취소 뒤 결과 거절.
- 만료 검사 직후 트랜잭션 대기 중 기한이 지나도 heartbeat·결과 제출 거절.
- 미지원 제공자/런타임과 잘못된 입력 거절, 예산 초과 보고액 보존.
- SQLite 재시작 후 상태·diff·비용·승인 복원.
- 운영자/워커 권한 구분, 토큰이 관제 응답에 포함되지 않음.
- 실제 HTTP에서 API와 별도 워커 모듈의 등록→claim→결과→사람 수락.
- 모의 어댑터 취소, heartbeat 거절 뒤 실행 중단, 실패 보고.

### 초기 브라우저 검증

실제 중앙 API와 별도 워커 프로세스를 연결했다.
관제실에서 작업 등록→실행 승인→결과·합성 diff·$0.001000 확인→결과 수락을 수행했다.
수락 후 종료 상태와 승인 입력 숨김을 확인했다.
추가 UI 점검에서 사용자 입력의 HTML 비실행, 조회 중 입력·포커스 유지,
390px 화면에서 가로 넘침 없음을 확인했다.

### 초기 컨테이너 검증

`docker build -t project-hivemind:local .` 성공.
별도 테스트용 Compose 프로젝트에서 중앙 서버와 워커를 실행했다.
생성→승인→컨테이너 워커 결과→수락을 확인하고, 중앙 서버 재시작 후 기록 복원을 확인했다.
컨테이너에서 대시보드 파일이 정상 제공됨을 확인했다.
검증용 컨테이너·네트워크·볼륨은 종료 후 제거했다.

### 초기 검증 범위 밖

초기 모의 검증에는 실제 Codex·Claude·ChatGPT 연결, 실제 Git diff 수집, ECS/Cloudflare 실행,
다중 사용자 인증, 외부 과금 상한, 장애 내구성과 성능은 검증하지 않았다.
Node 24의 내장 SQLite는 실험적 기능 경고를 표시한다.
이는 초기 모의 골격의 검증 범위다. 실제 Codex·Git diff 추가 검증은 위 절을 참조한다.
