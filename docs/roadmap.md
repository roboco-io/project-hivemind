# 개발 로드맵

일정과 인프라 비용은 실제 저장소·제공자·리전을 정한 후 산정한다.
현재 구현 범위와 후속 단계를 구분한다. 검증 결과는 해당 테스트·실행 기록에서 확인한다.

| 단계 | 범위 | 완료 조건 |
|---|---|---|
| 0. 로컬 모의 골격 | 중앙 API, SQLite, Web UI, 모의 워커 구현 | 승인→claim→결과→수락. 권한·만료·지속성 검증 |
| 1. 로컬 실제 실행 | Codex·Claude CLI, 공통 Git worktree·diff·테스트 계층 구현 | 고정 커밋 실행, 원본 변경 보존, 실패·취소·시간 제한과 실행 근거 검증 |
| 2. 원격 ECS MVP | 작업 시작·중지, 원격 워커 인증, 결과 보관 | 격리된 두 워커 병렬 실행. 유실·중복·종료·정리 검증 |
| 3. 연결 도구 확장 | MCP 서버와 ChatGPT UI, 제공자별 도구 승인 | 어느 도구에서도 상태 일치. 사람의 승인 권한 유지 |
| 4. 계획·비용 최적화 | 목표 분해, 작업 DAG, 모델·런타임 라우팅 | 사람이 계획 승인. 실제 비용·실패율·지연으로 효과 비교 |
| 5. 운영 확장 | PostgreSQL, 영속 워크플로, 조직 인증, 이력 조회 | 장애 복구·권한 격리·이벤트 재생·비용 정산 검증 |

## 다음 구현 단위

1. 로컬 테스트 실행을 별도 보안 런타임으로 옮긴다. worktree의 파일 격리와 실행 코드의 보안 격리를 분리한다.
2. Codex·Claude 실행의 도구 승인과 진행 이벤트를 중앙 이벤트로 확장한다.
3. 출력·patch를 파일 결과물로 보관하고 해시·페이지별 조회를 추가한다. 현재는 크기를 제한한 값과 worktree를 보존한다.
4. 사용량 원본·가격표 버전·금액 확정 상태를 저장한다. 현재 두 실제 제공자의 금액은 미확정이다.
5. ECS 도입 전 이미지·네트워크·IAM·인증·비밀 주입·종료 정리 계약을 검증한다.

운영 설정 변경으로 실행 중 테스트 프로필이 바뀌지 않도록 한다.
서버 재시작은 새 작업의 base snapshot을 갱신하지만 기존 작업의 base commit을 바꾸지 않는다.
현재 재시도는 새 작업 생성이다. 자동 재시도 전에는 시도별 실행 기록과 결과 제출 멱등성을 추가한다.

## 기술 전환 조건

| 전환 후보 | 도입을 검토할 조건 |
|---|---|
| PostgreSQL | 중앙 API 다중 인스턴스, 복잡한 조회와 관리형 백업 필요 |
| 영속 워크플로 엔진 | 장시간 승인 대기, 여러 단계 복구·재시도·보상 필요 |
| SSE / WebSocket | 2초 조회 지연이나 부하가 실제 관제에 문제를 일으킴 |
| 제공자 SDK / App Server | CLI 일회 실행을 넘어 지속 대화·인증·도구 승인 제어 필요 |
| React / Next.js | 제품 화면과 상태 관리가 현재 정적 UI의 범위를 넘음 |
| Cloudflare Containers | 검증한 가벼운 작업에 ECS 외 실행 경로가 필요 |

컨테이너 가격만으로 최저 비용을 판단하지 않는다.
모델 사용량, 재시도, 실행 시간, 네트워크와 운영 부담을 함께 측정한다.
소스와 문서의 라이선스는 Apache-2.0이다.
공개 제품명과 서비스 제공 범위는 제품 출시 전 별도 결정한다.
