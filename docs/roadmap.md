# 개발 로드맵

각 단계는 앞 단계의 관찰 가능한 완료 조건을 통과한 뒤 진행한다.
일정과 인프라 비용은 실제 대상 저장소·제공자·리전을 정한 후 산정한다.

| 단계 | 결과물 | 완료 조건 |
|---|---|---|
| 0. 로컬 최소 골격 | 중앙 API, SQLite, Web UI, 모의 워커, 문서와 테스트 | 승인→claim→결과→수락 연결. 권한·만료·지속성 검증 |
| 1. 실제 개발 실행 | 저장소 작업 공간, Codex 어댑터, 실제 diff와 테스트 결과 | 지정 base commit에서 실행. 비밀 비노출, 취소·승인 전파, 실제 사용량 근거 검증 |
| 2. 원격 ECS MVP | 이미지, 작업 시작·중지, 원격 워커 인증, 결과 저장 | 격리된 두 워커 병렬 실행. 유실·중복·종료·정리 동작 검증 |
| 3. 연결 도구 확장 | Claude 어댑터, 중앙 API용 MCP 서버와 ChatGPT UI | 어느 도구에서 조회해도 상태 일치. 사람의 승인 권한 유지 |
| 4. 계획·비용 최적화 | 목표 분해, 작업 DAG, 모델·런타임 라우팅 | 사람이 계획을 검토하고 승인. 실제 비용·실패율·지연으로 효과 비교 |
| 5. 운영 확장 | PostgreSQL, 영속 워크플로, 조직 인증, 이력 조회 | 장애 복구·권한 격리·이벤트 재생·비용 정산 검증 |

## 다음 구현 단위

1. `RepositoryWorkspace` 계약과 로컬 Git worktree 구현을 추가한다. 허용 저장소와 base commit을 필수로 받는다.
2. 실제 실행 전후의 Git 상태를 수집한다. 사용자 변경 사항과 실행 결과를 섞지 않는다.
3. Codex 어댑터의 실행 이벤트·도구 승인·취소를 공통 이벤트로 매핑한다.
4. 모델 사용량 원본과 가격표 버전을 별도 저장한다. 예상 비용과 확정 비용을 구분한다.
5. ECS 런타임을 구현하기 전 이미지, 네트워크, IAM, 비밀 주입과 종료 정리 계약을 테스트한다.

각 단위에는 기능 동작, 오류 복구와 권한 거절을 확인하는 테스트를 포함한다.
현재 `runId`는 실행 하나를 식별한다. 자동 재시도를 도입할 때는 시도별 실행 기록,
결과 제출의 멱등성 키와 재시도 정책을 먼저 추가한다.

## 기술 전환 조건

| 전환 후보 | 도입을 검토할 조건 |
|---|---|
| PostgreSQL | 중앙 API 다중 인스턴스, 복잡한 조회, 관리형 백업 필요 |
| 영속 워크플로 엔진 | 장시간 승인 대기, 여러 단계 복구, 재시도와 보상 동작 필요 |
| SSE / WebSocket | 2초 조회 지연이나 조회 부하가 실제 관제에 문제를 일으킴 |
| React / Next.js | 복잡한 화면 상태, 라우팅과 제품 UI 규모가 현재 정적 UI의 범위를 넘음 |
| Cloudflare Containers | 검증한 가벼운 작업이 ECS 외 실행 경로를 필요로 함 |

컨테이너 실행 가격만으로 최저 비용을 판단하지 않는다.
모델 사용량, 재시도, 실행 시간, 네트워크와 운영 부담을 함께 측정한다.
소스와 문서의 라이선스는 Apache-2.0이다.
공개 제품명과 서비스 제공 범위는 제품 출시 전 별도 결정한다.
